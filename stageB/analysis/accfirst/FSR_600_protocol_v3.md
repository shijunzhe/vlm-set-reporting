## 1. 数据

**题目清单**

- `gui/data/conf_items.json`：600 道 ScreenSpot-Pro 题，ID 和截图路径都唯一。
- 与 pilot 在 ID 和截图路径上都不重叠；构建器每次都会断言这一点。

**运行目录与请求 ID**

- 每个请求的 meta 记录 run_version、setting、rep 和父请求 ID。

## 2. 方法身份（条款 A）

**两种配置。** 参数取自 `run_e12b.REGISTRY` 和 `MAX_TOKENS`：

| 模型 | M 配置 | D 配置 |
|---|---|---|
| GPT-6.1（gpt-6.1-sol，image detail auto） | min：reasoning_effort = low，max_completion_tokens = 16384 | default：不传推理参数，max_completion_tokens = 32768 |
| Sonnet 5.5（claude-sonnet-5-5） | min：thinking = between_tools，max_tokens = 16384 | default：不传 thinking 参数，max_tokens = 32768 |
| Gemini 3.8（gemini-3.8-flash，media_resolution default） | min：thinking_budget = 0，max_output_tokens = 16384 | 同 M |

**候选与代表**

- **candidate_id：** sha256(题, 模型, 设置, 父请求, 坐标) 的前 16 位，绑定原图上的点、父响应和坐标变换。评分、标注、比较和输出都使用这个点。
- **先评分，后比较：** 先用评分为每个簇选定代表，比较只在不同簇的代表之间进行。
- **代表固定后不再移动：** 若要移动，必须登记为另一个候选生成动作。

## 3. 确定性聚合（条款 B，实现：`gui/code/decision.py`）

1. **分簇：** 在"距离不超过较长边的 1.5%"图上取连通分量。
2. **簇代表：** 取 (Gemini p_hit, −来源次序) 最大的成员。
   - 来源次序固定为 GPT、Sonnet、Gemini。
   - 缺失的评分按 −1 处理。这是固定回退，不是校准过的概率。
3. **全局 S 规则：** 取 (代表 p_hit, 簇大小, −簇来源次序) 最大的簇。
4. **比较集合：** 按 S 的排序取前 3 个簇。不超过 3 个簇时取全部。
5. **胜次：** 一对代表在正反两种顺序下都选中同一个 ID 时，该代表记 1 次胜。未决、无效或两次不一致，双方都不记。
6. **C 规则：**
   - 至少有一方有胜次时，在胜次最多的簇中按 S 的排序字段选择。
   - 全部为零胜次时，回到 S 规则。
7. **与顺序无关：**
   - 结果不依赖回复文件顺序或并发完成顺序。规则只用集合与排序键。
   - 短标签如果碰撞，就确定性地加长位数，不删题。

**pilot 上的复验**

用同一份代码重算 pilot（`conf_eval.py --subset main`）：

| 流程 | 错误 |
|---|---|
| GPT min 两段放大 | 20 |
| GPT default 两段放大 | 16 |
| GLF | 20 |
| M-S | 13 |
| M-C | 12 |
| D-S | 13 |
| D-C | 11 |

前三个簇的上限在 pilot 上没有改变任何结果。

平局规则是对 pilot 代码的显式补全。若改成"一出现平局就回到 S"，M-C 会变成 13 错、D-C 变成 12 错。本协议采用上面的规则，并在报告中注明这一点。

## 4. 基线（条款 C、G）

- **GPT-default-zoom（主对照）：** GPT default 的 C1d，加 B4d 两段放大。
- **GPTx3（近预算单模型对照）：**
  - 三份独立的 GPT default 两段放大，重复编号 0、1、2。
  - 取最大的连通分量；平局时取包含最早合法采样的簇。
  - 返回该簇中最早合法采样的原始点。不取均值，也不调用 Gemini。
  - 三份全无合法点才算失败。
  - 是否真正等预算，由实际费用决定。
- **GLF（自实现的 GUI-Lens 式简化基线）：**
  - 第一轮必须给出裁剪，第二轮可以裁剪或点击，第三轮只能点击，最多 3 次调用。
  - 解析失败时回退到上一个区域的中心，并显式标注。
  - 不是原 GUI-Lens 的完整复现：没有 OCR 和检测器坐标参照，没有核验步骤，提示是我们自己写的。
- **报告用的单模型流程：** Sonnet-default-zoom、GPT-min-zoom、Sonnet-min-zoom。

## 5. 假设与统计（条款 F）

- **H1（唯一主检验）：** D-C 对 GPT-default-zoom。
  - 用按截图的配对 bootstrap（4,000 次，种子 20261014）。全分母错误差的 95% 区间上界小于 0，才算通过。
  - 同时报告修对、改坏和精确 McNemar。
  - 只有当 D-C 和 GPT-default-zoom 都没有任何未完成的题时，才执行 H1。
- **H1b：** D-C 分别对 GLF 和 GPTx3。两个精确 McNemar 的 p 值做 Holm 校正，用于"胜出"声明，同时报告区间。
- **H2（机制）：** D-C 对 D-S，M-C 对 M-S。只报告差值和区间，不设通过标准；不显著不能用来否定整个方法。
- **H3：** GPT 和 Sonnet 各自比较 default 与 min 的两段放大。只报告差值和区间。
- **其他报告项：**
  - 三项分解：原始候选都错 / 代表预选丢掉了正确候选 / 在代表之间选错；
  - 比较器在画出的代表点上的准确率，以及两种顺序一致的对数；
  - 簇直径和链式簇的数量；
  - 只有一个簇的题数及其错误数；
  - 每题的调用数、token、延迟、费用。部署费用和采集费用分开报告。
- **措辞：**
  - D-C 胜出，支持的是"完整流程更好"，不能自动归因于生成者的多样性。
  - 只有一个簇的题，只能称为"未触发跨簇比较"。

## 6. 失败与缺失（条款 E）

- **重试：** 运行器对每个请求最多尝试 4 次（首次加 3 次重试），只针对技术错误，不因内容重试。每一次物理尝试都计入调用和预算。
- **逐流程回退：**
  - 首次点击失败或没给出点：该模型在该流程中没有候选。
  - 放大失败或没给出点：使用首次点击的点。
  - 评分失败：该候选的分数记为缺失（−1）。
  - 比较失败：这一对不计胜次。
  - 某个伙伴模型失败：在已有的合法候选中照常选择。
  - 全部失败或回退都写入 flags。
- **无输出：** 一个流程没有任何合法候选时，记为无输出，算错，不移出分母。
- **未执行：** 请求从未执行的题（例如因预算暂停）标为 study_incomplete，不算模型失败。H1 只在没有这类题时执行。

**上限与停止规则**

- **项目上限：** 21,000 次物理尝试，$60。
- **在线核对：** 每个阶段开始前，核对"已用 + 本阶段预留 + 后续阶段预计"。会超出上限就暂停，申请补足，不删题。
- **暂停的含义：** 暂停时未执行的请求标为 study_incomplete。
- **执行顺序：**
  1. 先用种子随机抽 100 题（`--batch first100`）跑完所有阶段，只核对费用、传输和日志，不看识别结果，也不据此修改方法；

- **两类费用分开报告：** 采集所有对照臂的研究费用；D-C 的部署费用（只计 D-C 实际需要的调用）。

## 8. 运行入口（条款 F）

- **构建器：** `gui/code/conf_stages.py`。按 A、DA、GLF1 → B、DB、GLF2 → GLF3、S、SD → CMPA_M、CMPA_D 的顺序构建，每一阶段只读同一运行目录中前序阶段的回复。
- **dry-run 断言（`--check`）：**
  - 清单是 600 道唯一题、600 张唯一截图；
  - 请求 ID 唯一；
  - 没有 pilot 的题或截图；
  - 图像文件都存在；
  - 父请求在同一运行中；
  - 系统提示与 pilot 同阶段同模型的提示一致。
- **已通过：** A（1,800 次）、DA（2,400 次）、GLF1（600 次）。其余阶段依赖前序回复，在运行中按同一代码构建并检查。
- **运行器：** `gui/code/run_gui.py --subset conf_v1`，调用 `fsr_pilot/run_e12b.call`。
- **评估：** `stageB/analysis/accfirst/conf_eval.py --subset conf_v1`，与 pilot 复验使用同一份代码。
- **输入限制：** 发给模型的截图和局部图里没有真值框，也没有任何正确性信息。
